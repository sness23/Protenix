# Distillation — A Middle Path to v2-Shape Weights

Path C. Instead of training v2 from scratch on real PDB (Path A) or staying with v1.0.0's 368M architecture (Path B), you can train a *fresh v2-shape student* on **predictions generated by v1.0.0**. You get the 464M architecture without paying for full from-scratch training on real data.

This is a real technique used in practice (AlphaFold 2 used a version of it — "self-distillation with predicted structures"), but it's not the path Protenix v2 took, and **it will not match real-v2 quality**. It's a reasonable choice specifically when you want the v2 architecture's capacity envelope for downstream fine-tuning, and don't have budget for Path A.

## Why you'd do this

- You want v2's architecture for future fine-tuning capacity, but can't afford Path A.
- You have large unlabelled sequence corpora (MGnify, UniRef50, etc.) and want to use them.
- You're doing research on scaling or distillation itself — the student is the object of study.

## Why you might not

- **Student cannot exceed teacher.** The v1.0.0 teacher is your performance ceiling. If v1.0.0 fails on your targets, a student trained on v1.0.0 outputs will fail in the same places.
- **Compute is meaningful, not trivial.** Teacher inference over a useful corpus is ~10–20k GPU-hours — more than fine-tuning, less than from-scratch.
- **You get no confidence signal.** The teacher's confidence estimates are not ground truth; you can't distill reliable PAE/pLDDT from them.

If you want to experiment before committing: a good sanity check is to **distill a small student from v1.0.0 on 10k sequences**, train for 10k steps, and verify you recover ~95% of v1.0.0's lDDT. If that works, scale up.

## The architecture

Three components:

1. **Teacher**: released `protenix_base_default_v1.0.0`.
2. **Sequence corpus**: your unlabelled collection. See "Choosing a corpus" below.
3. **Student**: freshly-initialized v2-shape model (`protenix-v2` config), no pretrained weights.

The training loop is:

```
For each sequence in corpus:
    teacher_prediction = teacher.predict(sequence)
    student_prediction = student.forward(sequence)
    loss = structural_loss(student_prediction, teacher_prediction) \
         + distogram_loss(student, teacher_pair_repr) \
         + confidence_loss(student, teacher_plddt_calibrated)
    loss.backward()
```

## Choosing a corpus

You want sequences that are:

- **Numerous** (10M+ for a decent run).
- **Diverse** (sampled from protein families that cover chemistry space).
- **Have MSAs available** (teacher needs MSA input to produce good predictions).

Good choices:

| Corpus | Sequences | MSA availability | Notes |
|---|---|---|---|
| UniRef50 | ~50M | Via ColabFold server or local HMMER | Gold standard, diverse |
| MGnify | 100M+ | Via MGnify API | Metagenomic; good for broadening beyond RCSB |
| AFDB (AlphaFold Database) | ~200M | Sequence + AF2 predicted structure | Already has AF2 structures; good for hybrid teacher (v1 + AF2 ensemble) |
| ESM Atlas | ~600M | Via ESM-Fold already-predicted | If you want a different teacher mix |

For compute-constrained runs, **subsample hard**:

1. Start with UniRef50.
2. Cluster at 30% identity, keep cluster representatives (~5–10M sequences).
3. Filter by length: drop sequences <50 aa (unfoldable) and >500 aa (teacher is slow on these).
4. Intersect with sequences that have MSAs readily available.

A well-curated 500k-sequence corpus can be more effective than 10M of random UniRef.

## Step 1 — Generate teacher predictions

For each sequence, run MSA search, then teacher inference, and cache the output.

```bash
# Generate MSA for a batch of sequences (ColabFold server mode)
protenix msa --input my_corpus.fasta --out_dir ./corpus_msa --msa_server_mode protenix

# Convert each sequence to JSON with MSA
for seq in $(cat my_corpus_ids.txt); do
    protenix json \
      --input ./corpus_fasta/${seq}.fasta \
      --out_dir ./corpus_json \
      --altloc first
done

# Run teacher inference, save predictions + pair representations
# (You'll need a wrapper script that invokes runner/inference.py
#  with output-dumping flags to save pair reprs and pLDDT not just coords.)
python3 scripts/distill_teacher_infer.py \
  --teacher_ckpt $PROTENIX_ROOT_DIR/checkpoint/protenix_base_default_v1.0.0.pt \
  --input_dir ./corpus_json \
  --output_dir ./corpus_teacher_pred \
  --dump_pair_repr true \
  --dump_plddt true
```

**`scripts/distill_teacher_infer.py` does not exist in the repo** — you'll need to write it. Template:

```python
# Pseudo-code outline
import torch
from protenix.model.protenix import Protenix
from protenix.config.config import Config

def teacher_infer_and_dump(ckpt_path, input_json, output_dir):
    cfg = Config(model_name="protenix_base_default_v1.0.0")
    model = Protenix(cfg)
    model.load_state_dict(torch.load(ckpt_path)["model"])
    model.eval().cuda().bfloat16()

    features = load_features_from_json(input_json)
    with torch.no_grad():
        output = model(features, return_pair_repr=True, return_all_confidence=True)

    torch.save({
        "coords": output["coords"].cpu(),
        "pair_repr": output["pair_repr"].cpu().float(),
        "plddt": output["plddt"].cpu(),
        "sequence_id": features["sequence_id"],
    }, f"{output_dir}/{features['sequence_id']}.pt")
```

The point is you save per-sequence `.pt` files containing the teacher's coords + pair repr + pLDDT, then the student's data loader reads these instead of real PDB structures.

### Cost of teacher inference

- ~10–60 s per sequence (depending on length) on one A100-80G.
- For 500k sequences averaging 20s: ~2800 GPU-hours.
- Parallelize trivially with one sequence per GPU.
- Use `--dtype bf16` and `--enable_cache true` to maximize throughput.

## Step 2 — Train the student

You need a modified training loop that uses teacher predictions as the target instead of real structures. **This does not exist in the current Protenix training code**. You'll write a parallel training script.

Conceptually, replace the ground-truth-coord loss in `runner/train.py` with:

```python
# Standard training (pseudo-code)
loss_diffusion = diffusion_loss(student_pred, ground_truth_coords)

# Distillation
loss_diffusion = diffusion_loss(student_pred, teacher_coords)
loss_pair_matching = mse(student.pair_repr, teacher.pair_repr)  # optional: distill pair repr
loss_plddt = kl_div(student.plddt, teacher.plddt_soft)         # optional: distill confidence
```

Key design choices:

1. **Weight recipe.** Start with `alpha_diffusion=4.0`, `alpha_pair_match=1.0` (new term), `alpha_plddt=0.1`. No bond loss (teacher's bond geometry is already regularized).
2. **Disable EMA initially.** EMA helps when ground truth is stable; with noisy teacher outputs, EMA can suppress useful learning. Turn on after step 5k.
3. **Crop size 384** throughout. Larger crops don't help because teacher accuracy on long complexes is already limited.
4. **Mixed teacher**. If you have real PDB + teacher predictions, interleave them — e.g. 80% distillation, 20% real PDB. The real-PDB batches anchor the student to ground truth where available. This is close to what AF2's self-distillation did.

### Student training command (illustrative)

```bash
# Assumes you've added a "distillation_corpus" dataset config and written the loss additions
torchrun --nproc_per_node=8 runner/train_distill.py \
  --run_name v2_distill_student \
  --model_name protenix-v2 \
  --seed 42 \
  --dtype bf16 \
  --diffusion_batch_size 48 \
  --train_crop_size 384 \
  --max_steps 100000 \
  --warmup_steps 2000 \
  --lr 5e-4 \
  --ema_decay 0.999 \
  --model.N_cycle 4 \
  --triangle_attention cuequivariance \
  --triangle_multiplicative cuequivariance \
  --data.train_sets distillation_corpus_500k \
  --data.test_sets recentPDB_1536_sample384_0925 \
  --use_wandb true
```

(Again: `runner/train_distill.py` is a stub you need to write by modifying `runner/train.py`. Budget ~1–2 weeks of engineering.)

## Step 3 — Fine-tune on real PDB

Distillation gives you a student that mimics v1.0.0 at v2's capacity. To get *above* v1.0.0, do a final fine-tune on real PDB:

```bash
# After distillation finishes, fine-tune the student on real wwPDB
torchrun --nproc_per_node=8 runner/train.py \
  --load_checkpoint_path ./output/v2_distill_student/checkpoint/last.pt \
  --load_ema_checkpoint_path ./output/v2_distill_student/checkpoint/ema.pt \
  --model_name protenix-v2 \
  --lr 1e-4 \
  --max_steps 30000 \
  --train_crop_size 384 \
  --diffusion_batch_size 48 \
  [rest of stage 1 recipe]
```

This is cheaper than pure Path A because you're starting from an already-capable checkpoint. The 30k real-PDB steps let the student exceed v1.0.0 on the data v1.0.0 was trained on.

## Expected results

Rough expectation from the literature (AF2 self-distillation, TAPE, etc.):

- **Pure distillation student**: recovers ~90–98% of teacher's quality on teacher's distribution. Does not meaningfully exceed teacher.
- **Distillation + real-PDB fine-tune**: can exceed teacher by ~1–3% on benchmarks, because the student has more parameters and sees both distilled diversity and real ground truth.
- **Calibration**: worse than teacher. Distilled PAE/pLDDT are biased. Always do a Stage-4-style confidence-only fine-tune on real PDB at the end.

## Total budget recap

| Step | GPU-hours |
|---|---|
| Teacher inference over 500k seqs | ~2,800 |
| Student distillation training (100k steps at v2 size) | ~4,500 |
| Real-PDB fine-tune (30k steps) | ~1,350 |
| Confidence-only fine-tune (5k steps) | ~65 |
| **Total** | **~8,700 GPU-hours** |

Roughly a third to a quarter of Path A's cost. On 16 A100-80G for 2 weeks (~5,400 GPU-hours), you can do this if you're careful about sequence selection.

## Alternative: distill into something smaller

If your goal is not *v2-shape specifically* but "something high-quality at a custom size", consider distilling into `protenix-mini` or a custom small config. A mini student (~135M) trained on v1.0.0 predictions runs ~4× faster at inference, and if well-distilled retains 90%+ of teacher quality. This is arguably a more defensible research direction than replicating v2 from teacher.
